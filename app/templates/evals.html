Boring Data for Adults

Search Evals

How well can an AI answer NFL questions when it looks things up, and what does each right answer cost? The same model ({{ ev.model }}) answered every question; only the search tool changed. Every search tool was limited to the paper's {{ ev.allowlist|length }} approved sites. Answers were checked against ESPN's official game data and graded by {{ ev.judge }}. Run {{ ev.date }}.

What we found

With enough searches, every tool found every answer. Parallel found them in fewer.

10 results, ~{{ "%.0f"|format(pay["parallel-fast"].chars / 1000) }}K characters

One Parallel search hands the model the page text

Each Parallel search returned {{ pay["parallel-fast"].results|int }} results with excerpts from each page: about {{ "{:,}".format(pay["parallel-fast"].chars) }} characters per search for Fast and {{ "{:,}".format(pay["parallel-advanced"].chars) }} for Advanced. The answer is often already in that text, so the model can answer without opening pages. OpenAI's search results aren't visible to us; we can see its searches and the {{ pay["openai-search"].actions.get("open_page", 0) }} pages it chose to open.

{{ h5["parallel-advanced"].correct[0] }} · {{ h5["parallel-fast"].correct[0] }} · {{ h5["openai-search"].correct[0] }} of {{ hard5.questions|length }}: Advanced · Fast · OpenAI

That matters when searches are limited

With up to 5 searches on the {{ hard5.questions|length }} hard questions, Parallel Advanced answered {{ h5["parallel-advanced"].correct[0] }}, Parallel Fast {{ h5["parallel-fast"].correct[0] }} and OpenAI web search {{ h5["openai-search"].correct[0] }}. Every miss was “I couldn't verify it,” never a wrong answer. All {{ hard5.questions|length - h5["openai-search"].correct[0] }} of OpenAI's misses were whole-week questions (most yards, most sacks, leaders): three times it reached only schedule pages, and the other times it found stats for a game or two but couldn't confirm the rest of the week.

With room to search, it's a tie

At up to 20 searches, every tool got all {{ hard20.questions|length }} hard questions right (and all {{ easy.questions|length }} easy ones). Then the differences are cost and speed: Parallel Fast cost {{ money(h20["parallel-fast"].cost_per_resolved) }} per right answer vs {{ money(h20["openai-search"].cost_per_resolved) }} for OpenAI, and OpenAI was faster ({{ secs(h20["openai-search"].p50) }} typical vs {{ secs(h20["parallel-fast"].p50) }}).

Small print: one round of {{ hard5.questions|length }} questions at the 5-search cap. OpenAI enforces its own search limit and used 6 actions on {{ pay["openai-search"].over_cap }} of those questions, so it had slightly more room, not less.

How we ran it

  • Harness: Parallel's open-source parallel-search-evals, with our own NFL question sets (suite=local). Its built-in instructions to the model were not changed.
  • Answering model: {{ ev.model }} on every tool, with the harness's default reasoning setting. Judge: {{ ev.judge }} (the harness's grader), using our own strict right-or-wrong grading prompt. Answer keys come from ESPN's official game data, never from a search result.
  • Search budget: 20 searches or page fetches per question on the easy set and in the last section (the harness's standard budget); 5 on the 20 hard questions above, to see what happens when searches are scarce.
  • Our additions to the harness: OpenAI's built-in web search as a competing tool, a 5-search cap option, and the paper's {{ ev.allowlist|length }}-site allowlist on every search tool ({{ ev.allowlist|join(", ") }}).
  • Rounds: the easy set was run three times. The first round hit OpenAI's rate limit (11 questions failed before answering), so it was set aside and two clean rounds are shown. Each hard run was done once.
  • Cost: the answering model's tokens plus search fees at list price. Grading is not included.
